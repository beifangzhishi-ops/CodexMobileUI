# CodexMobileUI repository rules

## Purpose and authority
- Personal-use Android app eventually targeting the shared Codex App Server. **This worktree builds a separately installable visual edition:** its sample projects, messages and rules persist only in `src/demo/persistence.ts`'s isolated SQLite database, never in real Codex thread caches or the Gateway. Native Codex IDs and authoritative turns belong to a future distinct integration.
- Keep the project safe to publish openly. No secrets, real host URLs/IPs, passwords, OAuth tokens, signing keys, local user data or personal chat transcripts may enter source, docs, logs, fixtures, Git or release assets.
- This is staged implementation. Every feature must be described as tested or untested accurately; do not present mock or compile-only behavior as a validated Android APK.

## Architecture and scope
- Maintain strict modules for `src/demo` visual-only persistent mock state, `src/core` protocol/transport, `src/session` future host synchronization, `src/storage` real-thread caches, `src/auth` original PKCE components (not mounted by this visual app), `src/ui` React Native rendering, `gateway` isolated authentication/relay sources (untouched), and `tests`. The visual UI must never call `useCodexSession`, `turn/start`, `thread/list`, or Gateway endpoints.
- Never make the app depend on CCM/AOI; they are protocol references only. Do not modify CCM, AOI, the shared Codex proxy, or production authentication services without distinct user approval.
- Treat network payloads, model text, file URIs and all external links as untrusted. Never execute remote HTML/script or expose arbitrary Windows paths. Use authenticated HTTPS/WSS with host/thread/resource checks for all new endpoints.
- Preserve genuine App Server protocol and native messages; when live events are dropped, recover from authoritative `thread/read` rather than blindly replaying text. Correlate by thread/turn/item IDs and keep locally drafted text from silently auto-sending.
- Keep native history pagination and stream/cache reconciliation in the core modules, not inside Android screen components. Treat malformed server snapshots as a read failure, not a request to clear SQLite; never persist in-progress assistant text as a completed message. Serialize writes of drafts per host/thread.
- Stage 3 cross-conversation `@` references must use authoritative, host-scoped Codex thread IDs rather than embedding copied histories or creating duplicate conversation state. Verify the active App Server's actual reference/read/search capabilities before implementing the picker or agent integration; support bounded long-thread reads and explicit unavailable/stale-reference errors. Any new Gateway RPC requires authorization checks, allowlisting and tests before Funnel exposure.
- Review backwards compatibility and any changes to settled architecture with the user before implementing. Remove superseded names and dead files; do not keep inactive compatibility shims by default.

## Quality, tests, documentation
- Before changes, read this AGENTS.md, then README.md and relevant module contracts.
- Run `npm run check` and appropriate native/manual checks before marking work complete. Tests must never contact private real hosts or use actual OAuth secrets; use ephemeral loopback test servers.
- Use **CCM** for source changes, tests, native Android builds, docs and Git. Do not start a second build while a Gradle build is running. Native builds requiring subprocess privileges must use an approved CCM grant/action; never bypass approval using another tool.
- Windows Expo SDK 58 builds require official shared Android SDK CMake 3.31.6/Ninja 1.12.1 for long generated New Architecture paths. The checked-in `scripts/build-android-windows.ps1` selects it using a Windows-only Gradle override and checks JDK 17, Node 24, API 37, NDK 27 and signing. Do not overwrite SDK-managed binaries or pin Windows-only tooling for Linux builds.
- For an independently installable test APK, build the Release variant **with embedded JavaScript**; Debug requires Metro. The current Release variant is signed with a debug/test key, not a production identity. Preserve caches by default; use `-RegenerateCMake` only when intentionally changing the native build graph.
- Use `scripts/build-android-stable.ps1` as the primary Windows Android packaging entry, with a **separate visual-only short-path build root** `C:\Users\Songjx\cmui-visual-build-v030`, lockfile-matched dependencies, build lock and incremental Gradle/CMake caches. Do not use the mainline build root or join its `node_modules` to this worktree. The lower-level builder is for the staged checkout only.
- The visual Android builder must capture native Gradle stdout/stderr into ignored `.tmp/gradle-release-output.log` in the staged build root, preserve incremental caches and check the real exit code. PowerShell Transcript alone is not an adequate build failure log. Before retrying, verify the previous Gradle/build process has ended; never infer active work from a stale lock file.
- When the visual Release staged checkout has no `android/app/debug.keystore`, its native builder must generate an independent local debug/test keystore using JDK 17 keytool and retain it across incremental builds. Never import the OAuth application's keystore or commit any test signing key.
- Before native builds, verify that `app.json` Android package, Gradle `namespace`, Gradle `applicationId`, and the Kotlin entrypoint packages all match. The stable builder must fail early on mismatch; only the application Java/Kotlin source subtree is mirrored to purge obsolete package paths in the staged checkout, while retaining Gradle/CMake output caches. Native `android/` is gitignored: keep its generated files consistent locally and never assume version matching alone proves application identity.
- On native package changes, the stable builder must invalidate the cached React Native `android/build/generated/autolinking/autolinking.json` and its generated Java entrypoint when their cached `project.android.packageName` differs from Expo's Android ID; Gradle otherwise incorrectly reuses the old `BuildConfig` reference. Preserve all unrelated Gradle and CMake caches.
- Verify new APK versionCode/versionName, signature, embedded JS, SHA-256 and resulting artifact, preserving prior versions. Deliver validated APKs via CCM's Quark tool; require `FINISH`, 100% and matching local/remote sizes before claiming upload.
- Keep privacy-safe `src/diagnostics` log export accessible from the account page and the React error fallback, even if host loading or OAuth fails. Store only allowlisted scalar fields; never log hosts, URLs, secrets, token values, message text, thread IDs, raw errors or stacks. Maintain diagnostics privacy tests.
- Maintain README.md and AGENTS.md with actual current behavior. Keep architecture and roadmap docs consistent. Explicitly mark any feature that lacks real-host or Android-device validation.
- This feature worktree builds the independently installable visual Android application `dev.codexmobileui.visual` (0.3.0). Never substitute the OAuth application's `dev.codexmobileui.app` ID or register its OAuth scheme. Other worktrees maintain their own Android identities. Keystores, credentials, local runtime state and per-machine configuration are not tracked.
- For a Git repository, commit finished verified work. Push to existing configured remote only; never create or publish a public remote without separate authorization, never force push.

## Shared Windows launchers
- Normal MobileUI stop terminates only this checkout's Gateway. Never call shared-stack stop from MobileUI client shutdown, even when this checkout owns the stack. AOI stop is likewise bridge-only; Desktop closing is UI-only. Shared-stop remains explicitly requested and owner-authorized.
- Shared backend runtime selection must use only complete Codex Desktop installations and Desktop-managed runtime caches (newest executable modification time); no IDE/CLI alternative source. Preserve fingerprinted independent copies, leave active backends untouched, and keep source selection and tests identical to the AOI launchers.
- Shared Desktop launchers must stream child shared-stack output as it arrives; TCP proxy probes must be bounded and should not leave misleading progress bars. Preserve distinct runtime/backend/proxy startup phase messages and synchronize those modules with AOI.
- All shared Desktop launchers use `Global\\CodexSharedDesktop_SingleLaunch` to serialize detecting and starting the unique Desktop instance. If one Desktop exists, a second Desktop must not launch. Desktop closing does not stop the independently owned shared App Server or Gateway.
- The independently bundled shared-stack scripts in `scripts/` must maintain protocol and behavior parity with the AOI launcher across 6v/noha. This is source synchronization only, never a runtime dependency on AOI.
- A shared stack is owned only by the checkout that started its proxy and backend. Other checkouts may hot-attach after port, readiness, and process-identity checks; they must not adopt PID files, restart, or stop foreign processes.
- Shared-stack first-start/stop uses a cross-checkout Windows mutex; Gateway startup has a separate mutex and process ownership. Never auto-stop active Desktop, AOI, mobile clients, or shared work on launcher exit.
- Gateway remains loopback-only. Do not configure or enable a live Funnel endpoint without a distinct security review and explicit user authorization. Do not claim a health endpoint proves authenticated mobile or multi-client approval correctness.
- The owner authorized Funnel for the mobile client: only the authenticated gateway on loopback 48888 is exposed through dedicated public HTTPS 8443 on each host. Existing Funnel 443/10000 routes on the primary host must remain intact. Never expose the raw App Server, and keep the per-host 256-bit OAuth consent secret only in ignored local .env files. New mobile RPCs require explicit allowlist and integration tests before Funnel access.
- Model mobile OAuth on CCM's full authorization flow: validate PKCE client/redirect/state both before displaying consent and again on POST, round-trip safely escaped validated form fields, and issue persisted ten-minute, one-use authorization codes only on correct consent. Never auto-repeat a failed consent or blindly replay an authorization code; allow a wrong secret to be corrected on the same form. Android browser result handling must not depend on an unstable React callback. Gateway audit output must contain only safe path/status/timing and predefined event categories and timestamps, never supplied consent text, secrets, tokens, redirects, thread identifiers, or hostnames. Test long delays, restart, wrong-secret retry, code exchange and callback errors before deployment.
- Android OAuth action must always be clickable when idle and visibly enter a progress state on first tap; create a fresh AuthRequest/PKCE pair per attempt, surface cancellation/locked-browser/exchange errors, and never silently drop the first tap while preparing an asynchronous hook. Match native generated Gradle versionCode/versionName with app.json before each test Release build.
- The source gateway is maintained on 6v. The second host runs a deployment-only generated gateway package with its own AGENTS.md, README.md and private .env. Keep it in sync by packaging the compiled gateway with scripts/package-gateway-deployment.ps1 and transferring via private Tailscale file transfer, never copying .env or .state.
